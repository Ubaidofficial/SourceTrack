## 2. The Demo Ecommerce fixture arc — complete and verified

**Site:** `40ae22f2-1ec4-4653-a6cd-c1e116848a60` — **"Demo Ecommerce"**, `demo-ecom.sourcetrack.ai`,

(`nrsvpwzekfrdrzkoecfk`) and **absent** from prod (`zxjjjsipafojhzkkumvh`).

### 2.1 The seed-guard fix that unblocked it — #634

The guard could express *"seed the `de200000` fixture"* but not *"seed this staging site"*, and the
consequence was **not a refusal — it was a bypass**: `tinybird/tools/ingest_ndjson_to_tinybird.mjs`,
the tool actually reached for to seed a new fixture, had **no guard at all**.

- **Layer 1** — hardcoded `siteId.startsWith('de200000')` replaced with `STAGING_SITE_ID_PREFIXES`
  (original family, unchanged) plus `STAGING_SITE_IDS`, now holding Demo Ecommerce. This widens which
  staging *sites* may be seeded; it does **not** widen which *workspace* may be written to — that is
  still the append-token decode, which is the check that actually prevents a prod write. Pinned by a
  test asserting the newly-allowlisted site is *still* refused with a prod token.
- **Layer 2** — `assertStagingWorkspaceLive` was requiring the *seed target* to already have rows,
  conflating "is this the staging workspace?" with "does this site have data?" — the latter being
  false for any site you are seeding, precisely because it is empty. Decoupled.

## 3. 🔴 Filed this session — both open

### #636 — `--backfill-site` dry-run is not actually a dry run · **money-rail severity**

`--backfill-site` without `--confirm` announces `mode=DRY-RUN (no writes)` and warns *"No --confirm
flag → running DRY-RUN."* **It can still write.** The `dryRun` flag gates only the
`attributed_conversions` upsert; the **subscription side-effect writes are not gated at all**.
`runBackfill` calls the shared per-conversion path without the flag
(`nightly-attribution.js:454` — `await processConversion(site, conversion)`), and `processConversion`
defaults `dryRun` to `false`, so the side effect runs unconditionally (`:1167-1172`).

**Why this is the higher-severity of the two:** `--backfill-site` is explicitly documented as working
on **prod** (`nightly-attribution.js:20-21`). A false DRY-RUN label on a command that touches the
subscription revenue rail is a money-rail defect, not a logging nit. Verified at `d9a47c54`. **OPEN.**

### #637 — raw `site_key` in nightly-attribution logs · §6.5 violation

`nightly-attribution.js:433` logs the raw `site_key` in the BACKFILL target line. CLAUDE.md §6.5 is
explicit: `site_key` is the customer-facing tracking key and must never appear in UI, logs, or error
messages. Routine severity, unambiguous fix. Verified at `d9a47c54`. **OPEN.**
