## 2. 🔴 Real blockers — revenue / entitlement relevant

### B1. Free-plan users do real work before hitting the paywall — #629 (close #628 as dup)

`manual_spend` is `free: false` (`dashboard/src/lib/planFeatures.js:46`, mirrored
`api/lib/plan-features.js:72`). The backend correctly 402s on all five `/campaign-costs` routes. The
frontend gates the "Import Costs" button on `!isPreview` only, at **three** sites in
`dashboard/src/pages/Campaigns.jsx` (`:559`, `:704`, `:724`).

The damage is not the paywall, it's *where* the paywall sits. `validateFrontendRow` parses and validates
the pasted CSV **client-side first**, so a free user exports spend from Google/Meta, formats it to the
required columns, pastes it, watches it validate successfully — and only then gets the 402. The gate
lands after the only expensive step, so it reads as a broken feature rather than a plan boundary.

**Fix:** wrap all three sites (and the `:258` auto-open effect) in `hasFeature(site?.plan, 'manual_spend')`,
rendering a locked/upgrade variant otherwise. `hasFeature` is already imported at `:18` and used for
`csv_export` eleven lines from the first offending site.

**#627 did not cause this and is not held by it** — but #627 repaired the cost-gate CTA into a live
deep link (`/campaigns?import=true`), so a previously-rare dead end is now well-signposted. That deep
link is used in two places: `Integrations.jsx:1425` and, as of #627, `ReportBuilder.jsx`.

### B2. `ReportBuilderGate.jsx` admits free and trial users to the whole Report Builder — CONFIRMED, needs its own issue

Previously listed as unconfirmed. **Now verified in full** (see §0). The gate checks login state only;
`advanced_report_builder` is `free: false, trial: false` and is never consulted. Individual features
inside the page *are* gated (`saved_reports`, `dashboard_widgets`, `multi_touch_attribution`,
`csv_export`) — the page itself is not.

Larger surface than B1: free and trial users reach the entire page and every cost gate on it, which is
also how they arrive at B1's ungated button. Either the page consults the flag, or the flag is dead and
should be removed. **File this as its own issue** — it currently exists only as a bullet in #629's body.

### B3. #627's fix has never been click-tested in a real browser — but the environment question is now settled

Code-traced end to end, CI-green, merged, and #627 verified its five new strings in the **built** `dist/`
output rather than only in source. Never exercised by a human in a browser.
